2026-11-05. `codex/ux-principles-redesign`에서는 사용자의 새 요청에 따라 [UX 원칙 기반 계획](../../docs/workflows/ux-redesign/00-progress.md)이 시각 설계를 대체한다. 중앙 편집기·도구 영역 구성과 공통 component·생성 경로는 유지한다. 아래 추출 기록은 이전 설계의 근거다. 현재 시각 값은 `tokens.json`의 `herdr.ux`다.

Tool Windows는 IdeaSettings의 독립 `windows` 페이지에서 공통 관리 목록과 우측 위치·표시 상세를 사용하며, keymap은 검색·액션 선택·상단 추가/변경/제거와 우측 개별 chord 상세를 사용한다. 두 페이지는 Apply/Cancel draft를 유지한다. 키맵의 staged/CAS와 macOS Ctrl/Meta 구분도 보존한다. 현재 계약은 [공통 컴포넌트](COMPONENTS.md)와 [T31 구현 결과](../../docs/workflows/ux-redesign/results/T31-settings-cleanup.md)를 따른다.

## 공통 시스템을 핵심 산출물로 구성

토큰의 단일 원본은 `design/idea/tokens.json`, 컴포넌트와 상태 규칙의 단일 원본은 `design/idea/ui.js`로 둔다. Herdr의 모드별 import 경계 때문에 각 모드에 필요한 사본은 생성 스크립트로 배포하고, 생성된 파일의 직접 수정을 금지한다. `--check`로 사본의 일치를 검증한다. 새 모드는 같은 생성 스크립트와 공개 컴포넌트 계약을 사용한다.

공유 범위는 typography/color/density, 버튼·아이콘 버튼·입력 상자·목록 행·구분선·탭·툴 윈도우 제목·팝업·다이얼로그·섬 마감이다. 메뉴는 선택/비활성/구분선/키보드 이동/Enter/Esc/선택 항목 스크롤까지 하나의 controller와 렌더러로 제공한다. 새 화면의 정상·빈·로딩·오류·포커스 상태와 긴 목록을 보여주는 예제 및 검증 절차를 남긴다.

레이아웃의 바깥 간격은 별도 계약이다. 창 프레임의 `root/body/work-body`에 일괄 gap을 주지 않는다. 각 섬 내부의 2px 테두리 영역을 합쳐 이웃 섬 사이 4px을 만들고, 좌우 스트라이프·하단 상태바 앞에는 별도 바깥 gutter를 추가하지 않는다. 사용자 지적의 바깥 여백을 재현해 수정하고 actual IDEA 화면과 비교한다.

## UI 구성

1. **공통 프레임**: 프로젝트와 브랜치, 실행 위젯, 검색·설정, 양쪽 스트라이프, 섬, 상태 표시줄. 사용자 창 크기·툴 윈도우 위치와 터미널 구조는 보존한다.
2. **Project와 툴 윈도우**: 중복 제목을 없애고 하나의 제목/액션 영역을 쓴다. 트리의 들여쓰기·행·파일 상태 색·활성/비활성 선택을 맞춘다. Structure/Commit/Find/Problems/Notifications/Agents/Terminal도 같은 셸을 사용한다.
3. **에디터**: 실제 Islands 탭과 소스 뷰, 줄 번호·현재 줄·오류·찾기·문서·코멘트·리뷰·이미지/마크다운을 같은 색과 크기 체계로 정리한다.
4. **검색과 이동**: Search Everywhere는 6개 탭·검색 필드·목록·하단 경로 구조. Recent Files는 실제처럼 툴 윈도우 목록과 파일 목록을 나눈 별도 UI로 만든다. Recent Locations는 실제 좌표 기반의 별도 목록으로 둔다.
5. **실행·HTTP·설정**: 구성 선택과 편집, 환경 선택, 새 터미널/에이전트 메뉴, 설정의 카테고리/본문/버튼 영역을 맞춘다. 팝업이 길어지면 목록만 스크롤하고 선택 항목이 보이도록 한다.

## UX 선정

- 실제 활성 키맵의 macOS 상속 변환을 적용한다. 최근 파일 `⌘E`, 최근 위치 `⌘⇧E`, 액션 찾기 `⌘⇧A`, 파일 구조 `⌘F12`, 저장 `⌘S`이며, Mac parent에 직접 지정된 실행 `⌃R` 등은 Control을 유지한다. 전체 Ctrl→Cmd 치환은 금지한다.
- 클릭/키보드로 열린 창이 같은 결과를 낸다. 메뉴 `↑↓`·Enter·Esc, 검색 Tab·그룹 이동, 포커스 복귀, 파일/위치 뒤로·앞으로를 각각 확인한다.
- Esc는 현재 팝업/정보/검색 단계부터 닫고, 부모 상태를 불필요하게 바꾸지 않는다. 설정 Apply/Cancel과 저장 중 상태를 일관되게 처리한다.
- 오래 걸린 검색이 초기화 이후 결과를 되살리지 않게 한다. 비어 있음·로딩·실패를 각 화면 안에서 표시한다.
- 현재 Herdr가 제공하는 기능을 보존한다. 없는 디버거/IDE 엔진을 실행 성공으로 가장하지 않는다. 실제 엔진 차이는 검증 결과에 남긴다.

## 적용 순서와 완료 판정

| 단계 | 적용 내용 | 판정 |
| --- | --- | --- |
| A | 실제 앱 관찰·패키지/키맵 감사·기준 확정 | 실제 화면의 모양 설정과 주요 팝업, 현재 바인딩이 근거와 연결됨 |
| B | 토큰·compact 밀도·macOS 키맵 추출 교정 | 생성한 값과 실제 앱의 표시/동작이 일치함 |
| C | 셸·탭·Project·툴 윈도우·에디터에 공통 적용 | 코너가 덮이지 않고 같은 컴포넌트의 크기/색 역할이 일관됨 |
| D | 검색·최근 파일/위치·메뉴·설정·실행 UI/UX | 주요 UI 구조와 키보드/포커스 흐름이 실제 앱과 거의 같음 |
| E | 설치·computer use 왕복 검증·기능 회귀·커밋 | CLI check, 실제 클릭/키 입력, 화면 비교, 배치/데이터 보존 확인 |

기하 비교는 Retina 배율과 창 크기를 구분한 **논리 px**로 한다. 고정 컨트롤은 기준과 1~2px 이내를 목표로 하고, 사용자가 조절하는 패널 폭/높이는 강제로 맞추지 않는다. 주요 화면 8종(프레임·Project/에디터·툴 윈도우·전체 검색·최근 파일/위치·실행 구성·설정·메뉴)을 실제 열어 확인한다. 확인하지 않은 화면/동작과 Herdr 엔진 차이는 미확인·제약으로 구분하고 전체 완료로 묶지 않는다.

이 계획을 기준으로 기존 미커밋 변경을 재검토하고 필요한 부분을 교정한 뒤 업데이트한다.
