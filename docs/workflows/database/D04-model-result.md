# D04 — SQL ranges and shared extractors

Implemented `mods/codenav/database-model.js` without imports or host/Node APIs. Public exports:

- `splitSQL(text, {dialect='mysql'}={})` returns trimmed `{start,end,text}` spans in original UTF-16 coordinates. Handles quoted strings/identifiers, escaped quote doubling, MySQL backslash escapes, nested comments, PostgreSQL dollar/E strings, MySQL DELIMITER and SQL Server GO batches/procedural blocks. Unterminated quotes/comments, misplaced DELIMITER and GO repetition fail explicitly. Client directives/terminators are excluded from server SQL spans. MySQL executable comments retain their original bytes.
- `queryCandidates(text, {start,end,caret=0,dialect='mysql'}={})` returns exact selection, nested parenthesized SELECT candidates (smallest first), current statement, and entire script when multiple statements exist. Candidate ranges are deduplicated. Entire-script/selection text is retained exactly: the caller splits selected/script text before transport; when a chosen range exactly matches an already-resolved routine block, it sends that verified block unchanged so its consumed DELIMITER is not lost. Nested candidates are lexical/syntactic suggestions, not proof that correlated subqueries execute independently.
- `EXTRACTORS` contains `csv`, `tsv`, `json`, `sql-insert`, `sql-update`, `where`, `markdown`, `html`, `xml` id/label pairs.
- `extractData({columns,rows,table?,schema?,database?,driver?,primary_keys?},format='csv',options={})` returns text. `columns` accepts names or `{name}` objects. Options: `headers` (default true), `nullToken` (default literal `\\N`), `keys` (SQL predicate key names). SQL UPDATE/WHERE reject missing keys; UPDATE excludes key columns from SET. Table qualification follows driver syntax; strings escape single quotes, and MySQL strings containing backslashes use UTF-8 hex conversion to avoid SQL_MODE ambiguity. Unsafe integer Numbers reject; exact decimal strings/BigInts remain exact. Binary accepts the engine's `{type:'binary',base64:'AP8='}` representation as well as explicit hexadecimal. No script evaluation.
- `parseImport(text,format='csv',options={})` supports CSV/TSV/JSON and returns `{columns:[{name}],rows}`. Delimited values remain strings except an **unquoted** configured NULL token. Empty strings and literal NULL-token strings export quoted, preserving the distinction. Headers default on; with `headers:false`, names come from `options.columns` or generated names. Inconsistent row widths/JSON object keys and malformed quoting reject.

Validation: `node design/idea/check_database_model.mjs` passed, covering comment/quote delimiters, PostgreSQL E/dollar quotes, MySQL routines, SQL Server GO/procedural blocks, UTF-16 range identity, nested choices, exact selected whitespace, CSV/TSV Unicode/NULL/multiline round trips, JSON BigInt/unsafe numbers, SQL escaping and key requirements, binary values, HTML/XML and every advertised extractor. `git diff --check` passed for the new model/check files.

Limitations: this is a conservative lexer, not a dialect parser. It does not infer dialect-specific semantic dependencies, expand SQL Server GO repetition, or parse every vendor procedural construct. CSV/TSV cannot recover SQL types from text; callers should map columns/values in the preview before mutation. JSON exact large integers must be encoded as strings. The integration owner is responsible for wiring the single extractor to Copy/Export, import preview, the SQL chooser, and native UI verification.

Final integration also rejects MySQL compound routines lacking a custom DELIMITER and retains SQLite trigger BEGIN/END/CASE bodies as one statement. Model tests and the editor transport regression cover both resolved routine execution and rejection of fragmented bodies.
