## Findings and reconstruction decisions

| Question | Static observation and exact entry point | Decision for this implementation | Coverage |
|---|---|---|---|
| Global data sources | `database-plugin.jar!/META-INF/plugin.xml` and `intellij.database.core.impl.jar!/intellij.database.core.impl.xml` register both application and project services for `DataSourceStorage` and `DataSourceStorageShared`. `DataSourceStorage$App` uses the application message bus and `loadFromStorage(application, null)`. `DataSourceStorageShared$App` has `@State(name="dataSourceStorage", Storage("dataSources.xml"))`. `messages/DatabaseBundle.properties` explicitly labels global data sources and says deletion affects all projects. | Keep saved profiles at engine/application scope; source IDs must survive space switches. Session-only password storage and the JSON file format are local requirements, not claims about IntelliJ secret storage. | Answered for scope; secret persistence deliberately uninvestigated. |
| SQL action and selection | `RunQueryAction.getExecOption()` selects `DatabaseSettings.execOptions[index-1]`; `RunQueryAction$Alt1` supplies index 1. Plugin action `Console.Jdbc.Execute` uses shortcut inheritance `Console.Execute.Multiline`. `QueryActionBase.getInfoClassic()` calls `JdbcConsoleProvider.findScriptModel()`. That calls `ScriptModelUtil.getSelectionForConsole()` and `adjustModelForSelection()`, which work with editor `TextRange` and configurable `execSelection`. | One SQL Run action should resolve the current editor range before sending SQL. Preserve selected original text and expose the chosen scope. Use the repository effective keymap for Cmd/Ctrl handling; these JARs alone do not establish the effective macOS shortcut. | Answered for delegation/range model; exact active settings and effective key binding unobserved. |
| Nested/current/block candidates | `JdbcConsoleProvider.chooseStatements()` builds maps of distinct statement ranges from `ScriptModel.statements()`, reads `execInside` / `execOutside`, calls dialect `EvaluationHelper.isStatement()` / `isBatchBlock()`, and uses `smallToLarge()` to prepare chooser candidates. The ambiguous branch calls `IntroduceTargetChooser.showIntroduceTargetChooser()` with resource `statement.chooser.header`; choosing an item passes `ScriptModel.subModel(chosenRange)` to the callback. | Show candidates when more than one meaningful nested/current/block range exists. Candidate ordering should be predictable, ranges should be inspectable, and executing one must send that original range only. A local lexer is a deliberate bounded substitute for IntelliJ PSI/dialect parsing. | Answered for existence and callback boundary; complete dialect grammar/default setting numeric mapping remains partial. |
| Grid editing and transaction controls | `SubmitMutations.submitChangesIfExists()` reaches `DataGrid.submit()`. `TransactionAction$SubmitAndCommitAction.prepareGrid()` returns that submission callback; `performTxAction()` sends `DataRequest.newTxCommit()` to the data producer. `TransactionAction$RevertAndRollbackAction.prepareGrid()` calls `GridDataSupport.revert()` over model index sets; its transaction action sends a rollback request. Plugin actions include `Console.TableResult.Submit` and `Console.Transaction.RevertAndRollback`. | Maintain a local mutation buffer with Apply/Revert, and show dirty/error/affected-row state. The local `db_apply` contract uses a single atomic transaction with conflict checking; this is an explicit product choice. Do not pretend it implements IntelliJ's complete session transaction modes. | Answered for separate mutation/transaction entry points; exact engine isolation and conflict policy unobserved. |
| DDL selection and hierarchy | `GenerateSqlActions$CopyDdlAction.actionPerformed()` obtains selected elements, calls `unique()`, then `doGenerateDDLUnderProgress()` and sends the generated text to `CopyPasteManager`. `GenerateSqlActions.doGenerateDDLUsingScriptingService()` handles `BasicMultiDatabaseRoot`, `BasicDatabase`, `BasicSchema`, flattens/filter elements and creates `ScriptingSingleModelTaskBuilder(..., ScriptCategory.CREATE_DEFINITION)` before `ScriptGenerators.makeScript()`. `CopyDdlFromDbAction` is a separate original-DDL path with a distinct action/resource label. | Offer generated DDL for multiple objects and parent hierarchy, deduplicate descendants covered by selected parents, and explicitly warn about unsupported metadata. Keep generated DDL distinguishable from original server DDL. Exact `CREATE DATABASE`/`CREATE SCHEMA` output is supplied by the local contract, not inferred from class names. | Answered for hierarchy-aware generation path; complete output/dependency ordering is unobserved. |
| Shared copy and export formatters | Database plugin registers `database.datagrid.extractorsHelper` as `DbExtractorsHelper`. `DbExtractorsHelper.getBuiltInFactories()` constructs SQL inserts, SQL updates, where-clause and XLSX factories; document-oriented grids request `JSON-Groovy.json.groovy`. In installed `grid-impl` module, `GridCopyProvider.performCopy()` calls `createExtractor()` then `GridUtil.extractSelectedValuesForCopy()`. Its factory path uses `DataExtractorFactories.getExtractorFactory()`, `ExtractorsHelper.createExtractorConfig()`, and `DataExtractorFactory.createExtractor()`; single-value copy has a dedicated formatter path. `DumpAction.createHandler()` routes console/grid/database-view sources while passing `DataExtractorFactory` / `ExtractionConfig`; `DumpHandler` creates an extractor using the same factory API. | Use one extractor implementation/configuration for grid Copy and Export, with explicit selected-vs-all-loaded row scope. A single cell may use the scalar formatter. CSV/TSV/JSON/SQL output must preserve NULL and escaping. Supported formats are local scope, not a claim of all installed IntelliJ exporters. | Answered for shared abstraction and separate output destinations; individual format byte semantics unobserved. |
| Import workflow | `DbImportDataPreviewManager` exposes CSV/database/query/table/scripted preview data types and methods including `formatDetected`, `previewUpdated`, `scheduleUpdate`, `joinPreviews`, and `processScheduledDetections`. These are signatures/inventory, not observed preview behavior. | Provide a reviewable parse/mapping preview before staging imported rows; use the same local CSV parser/column model used by the extractor. Do not assume that IntelliJ import reverses every exporter. | Partial: preview architecture confirmed, complete import semantics unobserved. |

## Implementation boundaries

The contract in [04-contracts.md](04-contracts.md) owns global JSON profile storage, session password handling, explicit async jobs, cancellation, pagination, transactional PK-based mutation conflict checks, and hierarchy DDL warnings. Those choices are supported by the requested product behavior, not attributed to the installed plugin. IntelliJ's PSI, JDBC session/task infrastructure, scripting extension points, XLSX exporter and Swing chooser should not be transplanted into the GPUI mod.

The original five research areas are covered sufficiently to guide implementation; import internals, effective IntelliJ user settings, dialect-complete nested SQL parsing, original server DDL, live cancellation/transaction behavior and actual visual/pointer interaction remain unobserved. They require separate authorized runtime evidence if exact IntelliJ parity is later needed. Verification of the new implementation must use its own local fixture and actual Herdr UI, not this artifact inventory.
