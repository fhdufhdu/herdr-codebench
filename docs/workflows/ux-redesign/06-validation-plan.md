# 검증 계획

최신 [ADE 재구성 제안](12-ade-rebuild-plan.md)은 다음 순서로 검증한다. 이번 턴은 계획 수립이며 아래 새 검증을 실행하지 않았다.

| 단계 | 실제 완료 판정 |
| --- | --- |
| UI 기반·T39 | 데모와 같은 창/배율/글꼴로 전체 프레임 비교, 다섯 위치·열기/닫기·빈 열 제거·경계 조절·포커스·큰 글꼴 확인 |
| 작은 편집 입력 선행 검증 | 격리 문서에서 입력/선택/Cmd+A·저장/IME·pending 처리를 실제 native 키로 확인. fixture handler 직접 호출로 대체하지 않음 |
| ADE 핵심 흐름 | 시험 프로젝트에서 탐색→AI 맥락 전달→작업/변경 검토→실행/실시간 로그→종료/오류/취소 및 재열기. 사용자 process는 시험에 사용하지 않음 |
| 통합 편집기 | 실제 입력/undo/dirty/CAS 저장/미저장 LSP/정의·참조 이동/Markdown 왕복. 통과 후 일반 텍스트 viewer 대체 |
| DB | 데모와 같은 소유 SQLite 화면/행으로 시각 비교 후 연결·편집·실행·DDL·추출·전송과 다섯 driver를 항목별 검증 |

각 작은 단위의 실제 화면·행동 결과와 남은 차이를 공유한 뒤 다음 단위로 이동한다. 자동 검사 PASS만으로 화면 정합/성능/OS 입력 성공을 판정하지 않는다. 코드 변경 시 기존 필수 생성/native 검사도 아래대로 수행한다.

| 대상 | 검증 |
| --- | --- |
| 공통 UI | sync_ui.py --check, check_system.mjs, design-system 실제 상태 예제 |
| 아이콘 | 모든 역할 매핑 존재·단일 원본·호출 호환, 실제 메뉴·툴바 표시 |
| 문서 | 기존 소스 뷰어·편집 진입과 source 이동 보존, dirty·저장·닫기·복원, Markdown 텍스트 모드 전환 |
| 셸 | 좌·우·아래 도구 영역, 패널 상태·크기·터미널 보존 |
| DB | 개선안의 출처와 구현·계획·미확인 구분, 기존 소유 SQLite fixture로 실제 UI |
| native | 변경 mod별 herdr-app check, 설치 후 CUA로 실제 진입점 확인 |
| 프로젝트 정렬 | 오른쪽 native 셀렉트, 세 기준·수동 순서 보존, 메뉴 열기·옵션 이동·선택·Esc·handle 해제 |
| HTML 데모 | 열린 문서 중복 목록 제거, 정렬 셀렉트, 좌우 위·아래 슬롯 접기·복원, 주요 상호작용·스크린샷 |

상세 검사는 조사와 구현 명세에 맞춰 보완한다. 자동 fixture의 성공을 실제 UI 완료로 간주하지 않는다.
