# ADE를 위한 재구성 제안

2026-11-06. 사용자가 제안에 동의하고 계획·진행을 요청했다. 현재 모드는 **전체 진행·첫 단위 구현**이다. 아래 순서와 경계에 따라 T39부터 시작한다. 기존 T28–T38의 부분 구현·검사 기록은 사실로 보존하되 새 구조의 완료 근거로 승계하지 않는다.

## 제품 목적

한 ADE 안에서 프로젝트를 열고, 코드를 탐색·편집하고, AI 에이전트와 작업하고, 변경을 검토하고, 실행 결과를 확인하는 흐름을 제공한다. DB는 이 개발 흐름을 지원하는 후순위 도구다. 화면의 수나 DB 클라이언트 기능의 수를 먼저 늘리는 것이 이번 재구성의 목표는 아니다.

사용자는 UI 구성 → 기본 기능 → 편집기 → DB 순서를 제안했다. 구현자의 권고는 이 큰 순서를 따르되, **UI 전체를 목업으로 끝낸 뒤 기능을 일괄 연결하는 방식 대신 공통 UI 기반을 만든 뒤 실제 작업 흐름을 작은 단위로 완성하는 것**이다. 이전처럼 HTML에서만 아름다운 표면과 실제 native 동작을 따로 완성하면 둘 사이가 다시 벌어진다.

편집기의 입력·단축키·IME는 별도 선행 검증을 권한다. 본격 편집기 구현을 3단계에 두더라도, 공개 runtime에서 가능한지 모르는 부분을 그때까지 미루면 UI와 기본 기능을 다시 설계할 수 있다. 이 검증은 편집기 전체 개발이나 병렬 기능 확장이 아니라 작은 격리 시험 하나다.

## 설계 원본과 새로 작성할 범위

- 시각·행동 원본은 승인된 `design/ux-redesign-demo.html`과 사용자의 최종 스크린샷·피드백이다. 기존 native 화면을 시각 기준으로 삼지 않는다. 데모도 변경할 필요가 있으면 이유와 차이를 먼저 제시한다.
- 화면 조립, 화면 상태, 이벤트 처리, 탐색·포커스·열기/닫기 흐름을 새로 설계한다. 기존 클래스 상속이나 기존 컨트롤의 스타일 덧씌우기를 새 구현의 출발점으로 삼지 않는다. 과거 코드는 필요한 개념·입출력·이행 자료로만 읽는다.
- OS 입력/IME, native 터미널, 문서 자료구조, LSP, DB 드라이버 등에는 적합한 검증된 라이브러리·공개 runtime 기능을 사용한다. 기존 앱의 화면 로직을 보존해야 한다는 제약과 라이브러리 재사용은 구분한다. 라이브러리는 도입 전에 실제 native 환경에서 필요한 능력을 확인한다.
- 사용자 파일·실행 process·터미널·Keychain·연결 설정·패널 크기를 새 구현의 시험 대상으로 삼지 않는다. 상태를 지우는 방식으로 구조를 초기화하지 않는다. 이행은 명시적인 입력/출력 경계에서 처리한다.
- 새 `idea` 경로를 작은 단위로 전환하고, 전환이 검증된 이전 경로는 제거한다. 장기적인 이중 구현은 목표가 아니다. 별도 지원 대상인 `codebench` 경로는 고립해서 보존한다.
- 현재 작업 브랜치 `codex/ux-principles-redesign`을 유지한다. Herdr 앱 본체 변경을 전제로 설계하지 않는다.

## 권장 순서

### 1. 공통 UI와 ADE의 틀

첫 산출물은 **ADE 전체 프레임 한 화면**이다. DB 탐색기부터 만들지 않는다.

1. 데모의 색·글꼴·밀도·여백·아이콘·경계·버튼 역할을 native 단위로 옮겨 공통 원본을 확정한다. 기존 토큰과 값이 다르면 데모와 실제 렌더를 기준으로 교정한다. 한 화면에 필요한 컴포넌트부터 만든다.
2. 상단 프로젝트/브랜치·실행·검색·설정, 중앙 탭/문서 영역, 좌우 스트라이프, 다섯 도구 위치(왼쪽 위/아래·오른쪽 위/아래·하단), 상태줄을 조립한다.
3. 도구 열기/닫기, 빈 열 제거, 경계 크기 조절, 탭 상태, 포커스, 스크롤을 실제 native UI에서 확인한다. 시연 데이터는 시연임을 표시하며 실제 기능 성공으로 보고하지 않는다.
4. 버튼·입력·메뉴·탭·목록·관리 목록·다이얼로그의 정상/선택/disabled/focus/empty/error/busy 상태를 컬렉션에서 확인한다. 관리 목록은 사용자가 선택한 상단 툴바 + 목록 + 상세 방식이며 순서 변경 버튼은 상단에 모은다.
5. 편집기 입력·선택·단축키·IME의 작은 격리 시험으로 구현 경계를 먼저 확인한다. 현재 알려진 Cmd+A/Save/SQL 실행 shortcut 실패는 미해결 자료로 취급한다.

완료 기준: 같은 창 크기·배율·글꼴에서 데모와 실제 ADE 틀을 비교할 수 있고, 열기/닫기·크기 조절·포커스가 동작한다. 공통 상태 예제가 실제로 그려진다. 한 부분이 어긋나면 그 부분을 마무리한 후 다음 부분을 만든다.

### 2. 핵심 ADE 작업 흐름

기본 기능을 메뉴 수로 정의하지 않고 다음 한 흐름으로 완성한다.

**프로젝트 열기 → 파일/코드 탐색 → AI에게 맥락 전달 → 작업 확인 → 변경 검토 → 실행 → 로그/오류 확인**

세부 단위는 프로젝트 전환·정렬/목록 관리 → 파일 탐색/탭·검색/이동 → 에이전트·터미널·맥락 첨부 → 변경/diff/검토 → 실행 구성·하단 결과/로그 → 설정·키맵·복원이다. 서로 다른 화면을 한꺼번에 다시 만들지 않는다. AI에 전송할 내용은 사용자가 검토할 수 있어야 하며 터미널 실행과 AI 입력을 구분한다.

실행 출력과 쿼리 결과의 위치는 하단 실행 결과로 일관되게 설계한다. 일반 터미널은 별도 도구다. 실행 중/종료/실패/취소, 최종 로그 보존, 재열기/재시작 후 상태와 소유권을 실제 process로 검증한다. 기존 native 불일치의 해결 표시를 그대로 물려받지 않는다.

완료 기준: 시험 프로젝트에서 위 흐름 하나를 창 밖 우회 조작 없이 수행할 수 있고, 프로젝트 전환·오류·취소 후에도 문서/터미널/실행 대상이 뒤섞이지 않는다. 설정은 공통 목록 UX와 적용/취소 경계를 따른다. 불필요한 메뉴/도구 모음 설정을 복원하지 않는다.

### 3. 통합 편집기

같은 문서·표시·입력·LSP 상태를 소유하는 편집기로 발전시킨다. 먼저 일반 텍스트 입력/선택/undo·redo/저장·충돌·닫기 → 한글 IME/폰트/스크롤 → 미저장 LSP 진단·hover·정의/참조 이동 → Markdown 원문/미리보기 순으로 확인한다.

입력 원문을 키 이벤트로 재조립하지 않는다. 사용자 keymap의 macOS Ctrl/Meta 구분과 재할당을 보존한다. 미저장 원문·LSP revision·디스크 저장의 책임을 분리하고 지연 응답이 최신 상태를 덮어쓰지 않게 한다. 지원되지 않는 API를 성공으로 가정하지 않는다.

완료 기준: 실제 타이핑·한글 조합·선택·단축키·파일 저장·미저장 진단·이동·Markdown 왕복을 확인한다. 이 기준을 통과한 뒤 일반 텍스트의 별도 viewer 경로를 제거한다. 비텍스트/미디어·diff는 역할을 따로 판정한다.

### 4. DB

ADE 틀과 기본 흐름, 편집기 뒤에 시작한다. 사용자가 승인한 두 DB 스크린샷은 이 단계의 시각 기준으로 고정한다. 기존 DB 화면·controller를 패치하는 계획은 대체한다.

순서는 탐색 영역 → 전역 연결 관리 → 중앙 표 읽기 → 셀 수정/변경 반영 → SQL 작성/블록·선택 실행/범위 확인 → 하단 실행 상태·결과 → 선택 범위 DDL → 공통 추출기 복사 → 파일 내보내기/가져오기다. MySQL·MariaDB·PostgreSQL·SQL Server·SQLite 다섯 종류를 범위에 포함한다.

완료 기준은 항목마다 실제 데이터 흐름과 데모 정합을 따로 확인한다. 처음에는 데모와 같은 구조·행을 가진 소유 SQLite fixture로 비교하며 네트워크 DB/형식별 동작은 별도 확인한다. 전역 연결과 Keychain의 기존 사용자 데이터는 새 구조로 이행할 대상이지 삭제할 대상이 아니다.

## 단계 안에서의 작업 방식

각 작은 단위에 다음 네 가지를 붙인다.

1. 데모에서 해당 부분의 화면·행동·상태를 지정한다.
2. 새 native 컴포넌트와 필요한 최소 상태 흐름을 작성한다. YAGNI는 현재 단위에 없는 기능을 미리 만들지 않는 기준이다.
3. 실제 화면에서 같은 크기로 비교하고 대표 행동·실패/취소를 확인한다. 검사 통과와 실제 UI 확인을 구분한다.
4. 전후 화면과 남은 차이를 공유하고 피드백을 반영한 후 다음 단위로 이동한다. 첫 실제 화면 확인 전에 여러 화면을 묶어서 설치하지 않는다.

공통 시각 값과 컴포넌트는 단일 원본으로 관리한다(DRY). native 기능과 적합한 라이브러리를 쓰되 화면마다 중첩된 추상화 계층을 추가하지 않는다(KISS). 이번 재계획만으로 개발·설치·커밋/푸시 완료를 표시하지 않는다.

## 바로 다음 제안

[T39 ADE 프레임](tasks/T39-ade-shell-rebuild.md)을 첫 구현 단위로 제안한다. 상단·중앙·다섯 도구 위치·상태줄의 전체 구도와 경계 조절을 하나의 실제 native 화면으로 먼저 보여준다. DB 전용 기능이나 편집기 본 구현은 이 단위에 포함하지 않는다.
