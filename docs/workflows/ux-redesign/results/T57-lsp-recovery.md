# T57 unchanged-buffer LSP and outline recovery

The previous session returned immediately whenever text/revision were unchanged, including after a transient sync failure. It also trusted an earlier acknowledgement after an engine restart, so a semantic request could report a missing lease while the source and outline remained stale until manual intervention. These are source-level recovery gaps; they do not establish the cause of every intermittent report.

The fresh backend now classifies transport unavailability and missing document leases separately from retired owners, stale revisions and identity failures. Owner conflicts receive only the same-owner bounded handoff retries described below. LspSession repairs only recoverable failures, resending the same in-memory owner/revision/text at 500/1500/4000 ms, at most three automatic attempts. Cursor-only updates cannot reset that budget. Manual retry starts a new bounded opportunity. No engine is killed, no other owner is closed, and owner IDs are not rotated to bypass conflicts.

Recovery invalidates old generations and serial/semantic waits so a cancelled or stalled earlier task cannot hold a newer repair. Server revision guards still reject older writes, and client owner/revision/generation checks reject late diagnostics/symbols. Outline errors/pending/ready metadata remains scoped to the current file/project.

Only the active file buffer observes existing engine identity every ten seconds. Observation itself never starts a service and does not notify/redraw when identity is unchanged. A changed PID/start/version causes the unchanged unsaved snapshot to synchronize again and refresh diagnostics/outline. Hidden buffers release their exact owned analysis session while retaining their native source buffer/undo. Reactivation creates a fresh owner only after prior owned retirement has completed. Automatic repair uses the normal existing backend discovery rules, including verified absent-service startup, without forcing an unhealthy existing service to restart.

Validation: `check_ade_lsp_recovery.mjs` passes unchanged-buffer transient recovery, bounded exhaustion/manual retry, bounded same-owner conflict retry without takeover, engine identity change with abandoned promises, quiet health observation, hidden-buffer pause, missing-lease repair and stale outline replies. Existing LSP/editor/EditorHost tests and native mod check pass. No live user file, credential, engine or installed module was changed by these tests.

Root owns actual UI installation and the reported TypeScript/Structure verification. The root's fresh round-trip fixture had already shown unsaved diagnostics 2→0, symbols, definition and reopen working before this recovery change. The inspected actual metadata contained no duplicate paths, but a later lifecycle audit found that every restored tab acquired a lease and all cleanup competed within the native 250 ms deadline. The approved follow-up now limits acquisition to the active file and gates same-path handoff on prior exact-owner close. This reduces cleanup pressure; it does not prove the identity of an already orphaned live lease.

Structure's refresh contract is `ade.analysis-request[projectKey] = {path,at}`. The active file editor consumes matching requests through its retained worker queue, coalesces rapid requests and records each consumed token once. Project/path changes before dispatch suppress the retry. The same `retryAnalysis` helper serves the existing LSP refresh button; Markdown recomputes its live headings without engine calls. Editor regression tests cover deferred dispatch, latest-token coalescing, exactly-once behavior, stale project/path suppression and Markdown refresh.

Approved ownership follow-up: restored inactive tabs do not claim analysis. File→file/project/DB/review transitions retire only the currently owned session. A path-specific close gate prevents another local project context from syncing that same absolute path until retirement completes. Final release directly reissues exact-owner cleanup for active and retiring sessions instead of awaiting their earlier promises. `check_ade_editor_leases.mjs` verifies two project buffers with the same absolute path, delayed close ordering, preserved unsaved text, retired callback rejection and review-mode release. Owner conflicts retry the same UUID at most three times to tolerate an HMR close completing slightly later; they never close or rotate around an unknown owner. After exhaustion, engine identity observation continues so a genuine new engine can recover the unchanged buffer.

Expiry/heartbeat integration: the engine owner is adding a 60-second stale-lease eligibility check only when a conflicting new owner attempts to claim the path; live owners are not arbitrarily replaced. The active client sends exact-owner/revision `document_touch` metadata every ten seconds, with no source text and no redraw on success. Missing touch leases enter the same guarded repair flow. After the short conflict budget exhausts, one additional same-owner claim is eligible after 65 seconds on the same engine; if a live owner still holds it, no further automatic claims occur. A changed engine identity remains an immediate recovery trigger. Tests use a controlled clock to verify the single delayed recheck, unchanged UUID, heartbeat identity/no-text, hidden pause and missing-heartbeat repair. The new heartbeat endpoint and expiry policy require the corresponding engine deployment; no live service was changed by these client tests.
