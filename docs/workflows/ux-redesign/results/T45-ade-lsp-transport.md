# T45 ADE backend and buffered LSP sessions

`mods/ade/backend.js` is a fresh authenticated transport over the installed Go engine boundary. Its protocol and installed paths come from `engine/main.go`, `engine/README.md` and `engine/install.py`; it imports no previous UI/controller.

It reads private engine state exclusively through the runtime `readTextFile` API, validates engine/PID/version through authenticated health, and never returns or logs the token. The existing healthy shared service is reused. An unavailable existing service is reported without stopping/restarting it. Only absent state permits launch of the verified installed binary using the same `~/.cache/herdr-codenav/engine.json` state/profile cache and default port 47822, background/no-parent/no-notify. Missing binary/configuration reports the installed path; no installation occurs. A failed request is never automatically replayed, including database mutations.

`mods/ade/lsp-session.js` owns one buffer lease, with a new owner for each session. `sync(snapshot,cx)` debounces 250 ms, serializes `document_sync` writes, then reads diagnostics and lexical tokens. Older owner/revision/path replies cannot update the current UI. Diagnostics preserve pending/matched/unversioned confidence. Pending/busy diagnostic publication has four bounded follow-up requests (500/1000/2000/3000 ms); editing and closing cancel owned timers.

`request(kind,cx)` supports hover/definition/references using the native selection head's UTF-16 offset. Missing selection stays explicitly unavailable, and remote buffers are rejected rather than sent to a local engine. Navigation waits for the text acknowledgement without waiting for unrelated semantic replies. `close(cx)` starts fresh lease cleanup immediately, bypassing earlier serial/discovery promises that HMR may have cancelled. It releases the exact sent owner/revision, with a same-owner last-acknowledged fallback only for an explicit stale-revision response, and discards late callbacks. Lexical tokens retain their native wire shape: line arrays of `[UTF16-length, category]` spans; the editor owns conversion to colors/absolute offsets.

Validation: `node --experimental-vm-modules design/idea/check_ade_lsp.mjs` passes authenticated identity, installed-binary shared singleton startup and occupied-port refusal, no mutation replay, debounce, ordered delayed writes, stale semantic responses, UTF-16 navigation, unavailable cursor/remote handling, close during pending sync, and bounded publication follow-up. These fake-transport checks do not establish actual language-server/toolchain behavior; root integration owns live editor/LSP inspection.

T49 service compatibility follow-up removes the separate ADE fallback state/cache. If the default state is absent but port 47822 answers, startup fails clearly without replacing or killing that unknown service. Existing invalid/unhealthy state also fails without relaunch. This keeps absent-engine startup on the existing global profile/Keychain identity. Tests cover the shared state/port and occupied-port refusal with fake transport only.

Critical HMR follow-up: the earlier serial wait could hang on a cancelled task and leave an orphaned lease. `backendCleanup` now reads/health-checks only the existing engine directly, never starting/restarting a service or waiting for cached discovery. Sync sends check the live session after discovery; attempted revision is recorded only immediately before send, and acknowledged revisions survive UI-stale responses. Tests cover never-resolving old serial work, pending-discovery bypass, blocked late dispatch, exact-owner fallback/tombstone and no fallback on owner conflict. A first sync that is already on the wire but has not acquired any server lease remains an explicit protocol limitation: current document_close cannot retire a not-yet-open owner. No existing user lease was forcibly closed or engine restarted.

Database refresh robustness follow-up removes normal transport's module-level connection/discovery cache as well. Each caller independently reads and health-checks the existing state before its single endpoint request; a cancelled overlay's promise cannot hold a subsequent tree/source refresh. Singleton startup rechecks state immediately before launch, and port binding remains the authority for races. A fake regression holds the first discovery unresolved while a later db_sources request independently receives the newly saved profile. In the actual UI, manual header refresh did retrieve the fourth owned profile; this does not establish the earlier automatic refresh's precise cause. Root/UI owner continues that automatic-refresh investigation. No live profile/service action was performed for this transport change.
