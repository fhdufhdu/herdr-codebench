# T10 설정·컬렉션과 목적 위치 이동 시안

2026-11-05. 사용자 후속 요청을 `design/ux-redesign-demo.html`에 구현했다. 현재 태스크는 HTML 시안이며 native 설정·이동 제어의 추가 변경은 수행하지 않았다.

## 이동 제어

사용자가 투박하다고 지적한 대상은 상하 이동 UI였다. 반복 이동 버튼, 숫자 순서 입력, 목적 위치 선택 메뉴를 검토하고 이름이 있는 대상 사이의 직접 이동을 시안으로 선택했다. 직접 지정 모드의 행 오른쪽 `⋯`를 열어 맨 앞 또는 다른 프로젝트 다음을 고른다. 현재 위치는 비활성이고 완료 후 결과 안내와 해당 행의 메뉴 버튼 포커스를 유지한다. 자동 정렬 후 수동 순서 복원도 유지한다.

W3C G219는 위치를 고르는 dropdown과 숫자 순서 입력을 재정렬의 대안으로 제시한다. 이 제품에서는 프로젝트 이름으로 위치를 알아볼 수 있다는 판단으로 목적 위치 메뉴를 선택했다. [W3C G219](https://www.w3.org/WAI/WCAG21/Techniques/general/G219)

보조 동작은 항목 맥락의 메뉴로 묶고 짧은 동사 label을 사용하는 지침을 참고했다. `⋯`의 실제 접근성 이름은 대상 프로젝트와 순서 이동을 함께 읽는다. [Fluent 2 Menu](https://fluent2.microsoft.design/components/web/react/core/menu/usage), [Fluent 2 Nav](https://fluent2.microsoft.design/components/web/react/core/nav/usage/)

드래그앤드롭 이동은 사용자가 제외했다. native 런타임의 기존 drag 기능과 가상 목록의 차이는 T09의 참고 조사로 남겼다. HTML에 항목 DnD handler를 추가하지 않았다. 패널 크기 조절은 유지한다.

## 설정창

화면·도구 영역·키보드·데이터베이스 항목을 왼쪽 탐색으로 묶었다. 밀도·UI 글자 크기·4개 도구 슬롯의 표시를 초안으로 편집한다. 취소는 적용하지 않은 변경을 버리고, 적용은 dialog를 유지하며 현재 데모에 반영한다. 확인은 적용 후 닫는다. 글자 크기는 11–16 정수 범위를 검사한다. 연결 관리는 기존 샘플 연결 창으로 이어진다.

## 확인용 디자인 시스템

데모 상단의 디자인 시스템 버튼에서 의미 색과 실제 hex 값, 타이포그래피, 기본·주요·비활성·선택·진행·오류 상태, 16/20px 아이콘, 문서 모드·레이아웃 설명을 볼 수 있다. 기존 HTML의 색 변수·아이콘 bank·button·mode 스타일을 사용한다. 예제 버튼과 문서 모드는 로컬 상태로 동작한다.

## 실제 브라우저 검증

- 프로젝트 메뉴의 목적 위치 3개·현재 위치 비활성, 맨 뒤 이동·맨 앞 복원·정렬 기준 왕복 후 수동 순서 보존을 CUA로 확인했다.
- 설정을 15px·compact로 바꾼 뒤 취소했을 때 body는 13px를 유지했다. 다시 열면 13으로 복원됐다.
- 14px·compact 적용 후 body 14px·목록 변수26px와 적용됨 안내를 확인했다.
- 오른쪽 아래 슬롯 표시 해제·적용을 확인하고 다시 표시·13px·normal로 복원했다.
- 디자인 시스템의 의미 색12개, 아이콘12역할의 크기2종24개, 기본 버튼 활성화 피드백과 문서 모드 선택 상태를 확인했다.
- 최종 브라우저 오류 로그는 없었다. 스크린샷은 codebench-settings-demo.jpg·codebench-design-system.jpg·codebench-project-sort.jpg에 저장했다.

실제 포인터 경계 드래그 검증은 남아 있다. native Codex 창 접근은 Computer Use의 안전 제한으로 거절돼 키보드 크기 조절 확인과 구분했다. 이 제한은 허용된 IAB의 설정·메뉴·컬렉션 조작을 막지 않았다.
